# Flask 渐进式重构：COS 备份适配

日期：2026-10-16。在前两批未提交改动上继续；不调整版本、不提交或推送 Git、不部署、不重启现有服务。

## 审阅与本批边界

已核对工作区、适用目录、README、前两批说明、备份/COS 实现、调用位置、测试及 Gunicorn 启动 hook；未发现适用的 AGENTS.md。保留所有已有改动。本批选择不访问数据库、不拥有线程或任务锁的 COS 适配边界，不继续拆归档、数据库恢复、storage 删除或调度器。

新增 `backend/backups/cos.py`，集中负责以下八个辅助函数的实现：

- 环境配置读取、对外状态与历史 COS 元数据组合。
- SDK 客户端构造及 SDK/配置缺失错误。
- 时间解析、对象分页列表、备份文件过滤与排序。
- 按既有保留数量清理旧对象。
- 本地归档的分片上传、大小核验、云端列表确认、清理与结果映射。
- COS 概况和列表失败时的状态响应。

协作关系：

```text
app.py 原管理接口 / 归档任务 / 自动调度
  -> app.py 同名辅助函数（原签名不变）
  -> backups/cos.py
       显式接收环境映射、前缀、保留数量、时区、时钟、SDK 工厂
       以及 get_client / list_objects / prune_objects 等所需回调
  -> 原 SDK 调用或现有上层配置写入
```

这些回调保留原 app.py 调用点之间的关系与可替换性，不传 globals 或应用整体命名空间。新模块不导入 app、Flask、数据库或 COS SDK，不创建客户端、线程、锁或全局实例，不读取环境变量或执行 I/O 初始化；SDK 仍在 app.py 原位置可选加载。未引入新依赖、客户端缓存或重试策略。

相对本批起点，app.py 净减少 127 行，只有八个 COS 辅助函数体和对应模块导入发生变化；其他顶层函数、路由装饰器、前两批模块均不变。

## 保持的契约

| 边界 | 保持内容 |
| --- | --- |
| 管理接口 | 全部 URL、HTTP 方法、endpoint、字段、状态码、错误提示和文件下载方式不变；登录/操作人/`manage_backups` 权限仍由原位置处理 |
| 环境/SDK | 原 COS 环境变量、前缀初始化时机和可选 SDK 逻辑不变；缺环境变量优先于缺 SDK；原内网域名标志和默认值不变，构造客户端仍为惰性操作 |
| 对外状态 | 不返回凭据配置字段；保留原 bucket/region/prefix、历史上传状态及错误字段和错误优先级；列表失败仍可返回 HTTP 200 并通过 COS 状态说明失败 |
| 列表 | 原 Bucket/Prefix/Marker/MaxKeys=1000 参数、单对象与数组 Contents、NextMarker/Marker 回退、缺 marker 时结束、文件过滤、大小转换、时间解析与稳定倒序排序不变 |
| 云端保留 | 仍只保留最近一个；传入对象列表时不重复读取、不重新排序，依次删除过期对象；不把空列表当作未传参数，也不取消原客户端创建 |
| 上传 | 仍使用 upload_file，PartSize=16、MAXThread=2、EnableMD5=True；先获取本地大小 → 上传 → head_object 大小校验 → 列表确认同 key/size → 清理旧对象 → 记录成功时间 |
| 失败 | 上传/校验/列表确认失败前不删除旧对象；SDK 构造和上传流程中的错误映射不变，成功字段和中文消息不变；删除中途失败不新增重试、补偿或回滚 |
| 手动导出 | COS 上传失败仍可下载本地 ZIP，X-COS-Backup-Status 为 error，保存 warning；授权连接先关闭，COS 操作仍在原任务锁内，配置保存和锁释放顺序不变 |

未调整任何事务、角色或片区/站点/检查表数据范围，也未改配置文件写法、业务数据库、迁移入口、前端、版本或 Gunicorn `app:app` 入口。

## 风险与后续

- 前两批的跨 Gunicorn worker 进程内锁/调度标记不共享、JSON 非原子写入、配置与任务竞争、下载前释放锁及数据库/storage 恢复非整体原子等风险，全部保持原样，未通过本批解决。
- COS 旧对象逐条删除没有事务；第二次删除失败时第一次可能已成功，本批新增测试明确保留这个事实，不声称任何失败都能完整保留旧对象。
- 保留策略仍依赖云端 LastModified 排序；在异常时间戳或并发上传下，确认新对象存在不等于保证该对象最终保留。解决这些问题应独立设计和验证，不能混入纯结构调整。

下一批适合先补充 ZIP 归档校验与成员路径安全测试，再提取相关校验职责，继续避开数据库恢复、storage 清理和自动调度。跨进程互斥仍应作为独立功能修复。完成本批后停止，等待审阅。
