## 范围与协作

首批工作区改动全部保留。重新核对 README、首批说明、备份实现、既有测试、Docker 配置和 Gunicorn hook；项目及适用目录未发现 AGENTS.md。归档、恢复、COS 与调度仍存在文件、数据库和后台执行耦合，因此本批选择更小的纯计算边界。

新增 `backend/backups/configuration.py`：

- 默认配置与频率间隔。
- 目标路径和执行时间规范化、时间字符串解析。
- 已合并配置的公共规范化，避免读写各维护一份相同规则；保留未知元数据字段，不修改传入字典。
- 下次执行时间计算及已保存执行时间的读取；通过具名参数显式传入时钟和时区。

```text
app.py 原配置 GET/PUT、手动任务和自动调度
  -> app.py 原辅助函数入口（签名保留；纯解析函数直接导入重导出）
  -> backups/configuration.py（只计算，不读写、不创建目录、不启动任务）

app.py read_backup_config / write_backup_config
  -> 原默认值合并与 JSON 文件读写
  -> configuration.normalize_backup_config
  -> 原时间戳、目录创建、文件写入顺序
```

新模块不依赖 Flask、app、数据库或 COS，也不接收 globals/整个命名空间，不新增依赖或初始化动作。锁的创建、获取/释放及自动任务启动位置不变。`app.py` 相对首批净减少 91 行；仅六个原辅助函数体变化，三个纯辅助函数改为导入重导出，其他原函数（包括全部路由和调度器）AST 不变。

## 保持的行为

| 边界 | 本批保持的契约 |
| --- | --- |
| `GET /api/management/backups` | 原认证/操作人、`manage_backups` 授权、频率选项、响应字段、文件列表、403/404/500 映射；只读不保存配置 |
| `PUT /api/management/backups/config` | 原 URL、方法、成功消息和错误提示；输入校验仍先于数据库访问，权限判断先于目录操作；目录写入探针 → 读取配置 → 保存配置 → 必要时清理旧目录 → COS 概况 → 响应 |
| 手动导入/导出 | 首批传输边界保持原样，继续调用 app.py 的配置读写及同一把任务锁；HTTP 和上传限额不变 |
| JSON | 损坏/不可读文件或非对象 JSON 回退默认；合法对象里的非法执行时间仍报错，不能悄悄修复；未知字段和原 UTF-8/缩进保留；读不写回，校验失败不截断原文件 |
| 时间 | 关闭/无效频率不调用时钟；已保存的合法下次时间优先（即使已过期）；每小时向后加一小时后去掉秒；日/周/月原算法不变，月仍为 30 天而非日历月；等于执行时刻则顺延 |
| 文件与事务 | 保留原绝对/相对路径规则；JSON 写成功后才清理旧目录；后续清理或 COS 概况失败不会撤销已写 JSON；授权连接仍在接口 finally 关闭，没有增加 commit/rollback |

未改数据结构、环境变量、迁移入口、Gunicorn `app:app` 启动方式、前端、角色或片区/站点/检查表数据范围。

## 已知风险与下一批

首批记录的风险仍成立，本批未修复：Gunicorn 多进程下的进程内任务锁/调度标记不共享；JSON 直接非原子写入；配置修改不受任务锁保护并可能清理旧目录；下载前释放锁；数据库与 storage 恢复不是同一事务。尤其不能把两 worker 启动冒烟误认为已解决多 worker 备份并发。

下一批适合在既有 COS 契约测试基础上提取云存储适配，继续保留调度和归档/恢复边界。跨进程互斥应作为独立功能修复评估、单独验证和交付，而非混入结构迁移。完成本批后停止，等待审阅。
