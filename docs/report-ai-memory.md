# AI 报告结果记忆与共享配置

## v5.6 共享报告工作区

- 每种报告全局共享一份最新保存配置，页面始终读取最后生成成功的成稿。日期、数据来源、选题规则及分类调整不会覆盖旧成稿，也不会自动调用 AI；用户重新生成后才应用。
- “已生成历史报告”仅展示生成请求的操作人、时间、日期范围及结果，不提供点击切换。报告生成日志与日期范围合并展示，报告特有的配置集中在同一分组。
- 各配置区记录最后保存人和时间。非油重点分类的人工调整按问题 ID 持久保存，后续 AI 分类不会覆盖有效人工结果。
- 配置与成稿只比较实际生效的数据范围、选题规则和分类，不比较保存人、时间或版本计数；自定义站点范围外的问题分类不造成误报。修改后提示“当前设置与成稿不同，保存后需重新生成才能应用。”，生成一致的新成稿后消失。
- AI 报告查看及生成仍需对应权限。报告候选数据和生成范围在报告模块内全局共享，其他巡检业务页面的片区、检查表权限不变。
- 升级需执行 `20260903_002` 和 `20260903_003` 迁移：新增共享配置表、生成操作人快照及分区保存人/时间元数据。迁移可重复执行，不删除报告或问题；回滚代码时保留这些数据。
- 本次仅提交并推送代码，不执行生产部署。部署时需同时更新前后端，后端现有入口会执行数据库升级，最新迁移版本应为 `20260903_003`。

## v5.5 复用规则

- 六类报告的 AI 选题、分析、追溯与建议返回值保存在 `inspection_report_ai_memory`，无自动过期时间，与报告历史快照分开保存。覆盖某个日期范围的历史报告不会删除 AI 记忆。
- 整批结果以报告 AI 操作类型、排序后的问题 ID 集合、完整问题数据、选题规则、实际提示词输入、提示词模板和模型计算指纹。仅查询顺序变化不会造成重算；数据内容、有效分类、优先级或相关月份语境变化则重新分析，避免陈旧结论。
- 原始问题描述即使被提示词截短，完整内容仍参与指纹。真实统计、整改状态、图表和 PPT 编排始终按本次查询重新计算，不缓存整份统计查询。
- 质量计量环节、非油“其他”分类和非油重点分类按操作类型与全局问题 ID 长期保存，不受报告日期和所选问题集合影响。“不纳入重点问题”也是有效分类结果。
- 原有三张分类表中有效的 AI / 人工分类直接使用；人工调整优先于 AI 记忆。原有本地兜底分类不是成功 AI 记忆，仍可以重试。
- 新分类每批最多 25 项，仅调用未命中的问题。无效类别、非法问题 ID、重复或缺失的分类不入库，不把失败当成永久结果。
- 采用 PostgreSQL 会话 advisory lock：相同整批输入去重；同类分类任务串行检查并重读记忆，避免重叠日期任务重复付费。等待 AI 时数据库连接处于 autocommit，不持有行锁或未提交事务。等待超过 600 秒不追加 AI 调用。

## 日志与权限

- `inspection_report_jobs.ai_generation_log` 保存进行中 / 失败任务日志。成功报告将当次日志一并写入 `report_payload.ai_generation_log`，读取最后生成成功的成稿时展示当次日志。
- 页面提供一个折叠的“报告生成日志”，不增加缓存配置开关，也不增加轮询接口。沿用已有任务进度查询及报告查看权限。
- 日志展示每个处理阶段的时间、问题数、调用 / 复用 / 兜底状态、耗时、模型、估算费用及整批历史结果的生成时间。
- 缓存命中时 `ai_called=false`、估算 token 和费用为零，不重复计入原 AI 用量日志。请求次数为应用层调用次数，SDK 自动重试不另行计数，费用不是供应商账单。
- 日志不包含提示词、问题原文、完整 AI 结果、API 密钥或数据库错误。AI 记忆无单独的公开读取接口；复用发生在后台验证报告权限并按共享配置筛选问题之后。

## 历史兼容与边界

- 升级前已保存的单问题分类立即复用。旧历史报告继续直接读取，但没有当时的逐阶段日志。
- 旧报告未完整保存原始 AI 响应，不能无损反推选题和分析缓存。第一次重新生成时建立新记忆，此后相同输入复用。不为补齐缓存主动调用 AI。
- 不自动删除问题的既有分类；问题内容编辑后，若单问题分类需要改变，应在已有分类面板人工调整。整批分析指纹仍会因内容变化而失效。
- AI 服务已接收请求、但进程在结果落库前退出时，无法保证供应商端 exactly-once 计费；重试仍可能收费。已成功落库的结果不受后台任务失败或进程重启影响。
- 提示词或模型变更会更新整批缓存键。未来修改响应解析 / 语义规则时，应同步提升 `MEMORY_VERSION`，防止复用不兼容结果。
